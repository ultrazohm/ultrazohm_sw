  What was built

  uz_dataviewer/ — a pip-installable Python project (pip install -e ., run with
  uz-dataviewer [files...]):

  - VS Code-style 3-pane layout (hello_imgui docking): navigation left, plot
  grid right, console bottom.
  - Navigation: load multiple .csv/.parquet files (background threads, UI never
  blocks), each run shown as a collapsible tree node with its logged signals
  (Matlab-style), a checkbox to activate/deactivate it, and right-click to
  remove.
  - Plot grid: runtime-settable (1×1, 1×2, 2×1, 2×2, 2×3, 3×3); signals are
  dragged from the tree and dropped onto plots; each cell's type is switchable
  between Time series and FFT.
  - Time plots: draggable A/B cursors with value/delta readout, CSV export of
  the cursor region (with "start time at 0" option), per-signal secondary y-axis
  via legend right-click, "Lock time axes" across plots — full feature parity
  with the old dataviewer.py.
  - FFT (the requested future extension, working now): pick a source time plot +
  signal; the spectrum is computed over the region between that plot's cursors
  (or its visible range), with Hann/Hamming/rectangular windows and log axes.

  Downsampling finding (the task asked to check this): the current dataviewer.py
  uses plotly-resampler's FigureResampler, which is plotly/Dash-coupled and
  can't be used with imgui_bundle — but its underlying core, the tsdownsample
  Rust MinMaxLTTB library, is framework-agnostic and is exactly what I reused.
  Each plot re-downsamples only its visible time range to a configurable point
  budget, with caching and view-padding so panning/zooming stays smooth on >1 GB
  logs. A pure-numpy min/max fallback covers the web build, where the Rust
  wheel doesn't exist.

  - Linux: packaging/desktop/build.sh (venv + PyInstaller) — ran it; the 292 MB

  - Web: packaging/web/build_web.sh builds the app wheel, downloads the official
