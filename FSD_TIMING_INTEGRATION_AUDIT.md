## Established application pattern

`docs/source/software/control/uz_pos_to_speed_pll/pos_to_speed_pll.rst` steps 1-6 (approximately lines 63-143) prescribes an instance-count macro in `uz_global_configuration.h`, a module init header under `src/include`, an init implementation under `src/sw`, a pointer in `src/globalData.h::object_pointers_t`, initialization in `src/main.c`'s `init_software` state, and per-cycle use in `src/sw/isr.c::ISR_Control`. The actual checkout's `main.c` initializes `uz_SystemTime` in `init_software`, then hardware IPs, then interrupts. `ISR_Control` calls `uz_SystemTime_ISR_Tic`, reads ADC/encoder, checks platform state, writes existing PWM duties, updates JavaScope and calls `uz_SystemTime_ISR_Toc`. It runs on the R5, as documented in `docs/source/guide/rpu_software/r5_statemachine.rst` and the source's RPU GIC setup.

The benchmark follows the pointer/init/ISR pattern. It is compiled and called only when `UZ_FSD_BENCHMARK_ENABLE=1`; the default is zero. The ISR hook runs only in `idle_state`. It passes synthetic, fixed golden input samples to a dedicated benchmark instance and never assigns to `Global_Data.rasv`, calls a PWM duty setter or changes GPIO/state-machine enables. Existing ISR PWM writes remain untouched. The platform documentation states the CPLD does not route gate signals in Idle. The benchmark must be run with the platform verified idle and the inverter unenergized.

## Timer provenance and measurement contract

`src/uz/uz_SystemTime/uz_AxiTimer64Bit.{h,c}` provides `uz_AxiTimer64Bit_ReadValue64Bit()` from the already initialized, cascaded 64-bit AXI uptime timer. The header defines `UZ_AXI_TIMER_CLOCK_FREQ` from BSP macro `XPAR_UZ_SYSTEM_TIMER_UPTIME_64BIT_CLOCK_FREQ_HZ`; the code uses an upper/lower/upper read to handle a low-word rollover. `src/uz/uz_SystemTime/uz_SystemTime.c::uz_SystemTime_init` starts it before interrupts, and `ISR_Tic/Toc` use the same timer for ISR profiling. `docs/source/software/platform/SystemTime/SystemTime.rst` documents the timer IP and the ISR timing API. Timer frequency is resolved from the target BSP at build/run time; no 100-MHz assumption is built into the benchmark. Unsigned 64-bit subtraction handles one wrap provided a measured interval is shorter than the full counter range. The benchmark measures a minimum empty read pair outside the timed step as timer overhead and stores both raw and corrected interpretation.

The benchmark records preload duration separately, one full `uz_fsd_mpc_step` duration per sample, raw min/max/mean, fixed-bin p95/p99 estimates, over-100-us controller samples, status and duty/schedule validity. Logging happens after the bounded run in the main loop, outside the timed ISR section. The existing `uz_SystemTime_GetIsrExectionTimeInUs` can be inspected separately; it is not misrepresented as the controller-only duration. Interrupt preemption and timer/bus contention can affect wall-clock samples; this is not a WCET proof.

## Build and safety constraints

The installed FSD public header supports the intended SI config exactly: `resistance_ohm=.51f`, `inductance_d_h=inductance_q_h=.002f`, `flux_pm_wb=.042f`, `period_s=.0001f`, `lambda=10.0f`, `UZ_FSD_MPC_SI`, `UZ_FSD_MPC_EXHAUSTIVE`, `UZ_FSD_MPC_SIMPLEX_FACE`, `UZ_FSD_MPC_SVM`. The p.u. rating fields are unused in SI. A build-selectable index later covers all six native SimplexFace selector/policy combinations, one per firmware build, so the production static pool of one is sufficient. The six fixed inputs are from the frozen JSON's first SVM/SI/SimplexFace record, including linear, sector, high-speed/low-voltage negative-id, signed-speed and zero-speed cases. They are a synthetic stateful sequence, not measured closed-loop plant data.

This Windows environment has neither Ceedling, Sphinx nor a Vitis cross-compiler on PATH; Docker access is denied. Target BSP `xparameters.h` is generated and is not present in the checkout. Consequently the actual target timer frequency, compiler optimization, target stack and on-target timing cannot be reported until the normal UltraZohm workspace build and execution occur.
